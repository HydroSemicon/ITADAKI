# 開発方針と未決事項

状態は「採用」「暫定」「未決定」で区別します。変更はPRで共有し、重要な判断は2人で合意します。

## 採用した方針

- Androidから着手し、Kotlin + Jetpack Composeで作る。
- 2人ともAndroid Studioを導入する。編集に使うAIはCodex / Claudeのどちらでもよい。
- 人向けの手順はCONTRIBUTING.md、AIの共通ルールはAGENTS.mdに集約する。CLAUDE.mdは共通ファイルを取り込む。
- 実装対象として合意した内容をリポジトリに残す。Google Docsの構想やAIの提案と区別する。
- 作業ブランチとPRを使い、もう1人の確認後にmainへ取り込む。
- OSSライセンスの採用は保留とし、外部への再利用を追加許諾しない。
- デモは架空データを使い、個人情報や実決済を取り扱わない。

## 初期構成の実装範囲

起動可能なアプリ、共通テーマ、架空2店舗の一覧、Compose Preview、起動画面のUIスモークテスト、ビルド用CIを用意する。

注文、会員登録、ポイント、位置情報、API通信、永続化はこの初期構成に含めない。画面のデザイン・文言・配色は議論用の仮置きとする。

## 暫定値

| 項目 | 現在の値・理由 |
| --- | --- |
| 最小対応OS | Android 8.0 / API 26。初期デモの下限として設定し、2人の実機・導入候補に合わせて再確認する |
| application ID | io.github.hydrosemicon.food。GitHub組織名を使ったデモ用の仮ID。debug版は末尾.debug |
| モジュール | appのみ。機能が増えたら分割を検討する |
| ビルド環境 | AGP 8.13.2 / Gradle 8.13 / Kotlin 2.2.21 / JDK 17を基準に固定する |
| UI依存 | Compose BOM 2025.10.01 / Activity Compose 1.11.0 |

## 次に合意すること

- デモで通したい操作。候補は店舗選択→メニュー→カート→注文完了。
- ホーム画面とメニュー・注文画面のラフ、共通の用語・部品・画面遷移。
- 店舗・商品・注文の共有データ形式と担当範囲。
- 店舗側の画面をデモに含めるか。
- 実機テストに使う端末・OSと、最低対応OS。

## 本格運用までに決めること

- バックエンド、認証、保存方法、加盟店ごとのデータ分離。
- 実注文・決済・POS・外部会員制度と連携する範囲。
- iOSへの展開時期とコード共有の必要性。
- コード・デザインの権利帰属、事業主体への移管、離脱時の扱い。
- リポジトリの公開範囲、GitHubのブランチ保護、管理アカウントと費用負担。
- 本番application ID、署名鍵の保管、配布アカウントと配布方式。

ブランチ保護、リポジトリの公開範囲、外部アカウントの設定は、この初期構成では変更していない。
